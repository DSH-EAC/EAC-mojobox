## 1. 共识总则

1. **方向确认**：采用"固定 HTTPS 入口 + 静态 JSON + 精确产物 + 递增序号 + 不可变批次 + 撤回记录"的供货方式。
2. **交付定位**：Mojobox 提供的是**资源供货清单**，不是安装计划，也不是市场内部数据库。
3. **流水线分工**（双方原文确认）：

```text
作者提供插件、皮肤、整合包及声明
                 ↓
Mojobox 收录事实，静态检查，导出 EAC 供货清单
                 ↓
EAC 市场导入、核对、转换成自己的市场目录
                 ↓
市场展示；用户确认后由宿主安装器或加载器执行
```

4. **责任分工**：

| 工作 | 负责方 |
| --- | --- |
| 插件代码、皮肤素材、原始发布包、组合内容和更新 | 上游作者；DSH-EAC 自制组合由其明确署名的组合维护者 |
| 包名、版本、来源、下载地址、真实摘要与大小的收录核对 | Mojobox |
| 兼容、依赖、冲突声明的原文与出处 | 作者提供，Mojobox 保存；**未知不补造** |
| 许可与授权材料 | 作者提供或来源已有，Mojobox 收录，EAC 市场按自身分发要求复核 |
| 读取清单、提取真实包元数据、导入内部目录 | EAC 市场 |
| 展示分类、推荐、评分、是否开放安装 | EAC 市场 |
| 本机环境判断、安装计划、启停、回滚 | 下游宿主安装器及对应加载器 |
| 运行验收及 `verified` 标记 | 下游在具体宿主和环境中验收后产生 |

5. **三状态不混用**：

| 概念 | 含义 | 不代表 |
| --- | --- | --- |
| `status: active` | 当前仍供给这条来源记录 | 不代表允许安装 |
| `status: withdrawn` | 停止供给该版本，保留撤回记录 | 不自动卸载用户已装内容 |
| 市场判定可安装 | 产物、来源、授权、兼容与安装入口满足下游规则 | 不代表运行验收通过 |

6. **运行状态**：一期所有供货记录统一 `runtime: "not-tested"`。静态检查通过不证明运行兼容、安全或安装成功；以后接入运行证据需另行约定格式，**不直接把该字段改成 `verified`**。

## 2. 一期导入模式（我方接受对方建议）

1. 一期采用 **"市场发布时导入"**，不要求客户端多源订阅。
2. Mojobox 增加一个 **EAC 专用导出**，不替换其现有网站 `catalog.json`；作者原始 `.dshpack`、`pack.json` 和插件产物保持原样。
3. EAC 市场实现 `supply.eac/v1` **导入器**，转换为现有 `MarketIndex` v2（我方目录校验器接受 MarketIndex v1/v2，不直接读取供货清单原文）。
4. 市场保留自己的 `publication.sourceId`、发布序号和发行历史；Mojobox 的 `sourceId`/`sequence` 仅作为**供货批次记录**，不冒充市场发布身份。
5. 导入产物发布为 EAC 自己的线上目录；**终端用户仍通过现有"刷新目录"机制获取**，客户端与内核热路径零改动。
6. 导入时机由 EAC 市场发布流水线安排，目标是供货方发新批次后尽快上架；具体频率另行同步。
7. **客户端直接订阅多个独立源属于后续独立任务**（需要独立来源缓存、冲突规则、撤回传播），不作为一期范围。
8. 不重新启用 Mojobox 冻结的 legacy Pack/Lock，不要求作者为接入市场重做整合包。

## 3. 格式共识

### 3.1 顶层结构（采用对方第 4 节）

```json
{
  "schemaVersion": "supply.eac/v1",
  "sourceId": "dsh-eac.mojobox",
  "sequence": 1,
  "revision": "2026-10-04.1",
  "generatedAt": "2026-10-04T12:00:00Z",
  "items": []
}
```

- `sequence`：正整数、严格递增，判断新旧的唯一依据；同字节重试不算新批次；低序号拒绝；不以时间覆盖顺序。
- `revision`：人类可读批次编号，每个序号唯一对应一个，不复用。
- `items`：完整供货快照，非增量补丁，允许空数组。

### 3.2 类型范围（一期）

| `type` | 一期处理 |
| --- | --- |
| `plugin` | 来源展示；满足市场条件后安装 |
| `skin` | 来源展示；核对真实加载方式后决定安装 |
| `function-pack` | 原始薄包下载与组合展示；满足额外条件后组合安装 |
| `appearance-pack` | 同上，不默认同时启用多套皮肤 |
| `material` | 仅展示与来源访问，**永不进入安装索引** |
| `skill` | **保留需求，但不作为 v1 接受类型**；不承诺收到即可安装 |

- 现有 `workflow` 包在无双方确认的映射前不导出，并在构建报告说明原因。
- 记录唯一键为 `packageName + version`（不含 `type`），同一产物不得通过换分类制造重复。

### 3.3 公共字段（采用对方第 5 节）

`type`、`packageName`、`version`（精确 SemVer，禁止 latest/范围）、`name`、`summary`、`source` 对象、`status`、`runtime`（一期固定 `not-tested`）、`withdrawnReason`（撤回时必填，不得泄露用户隐私）。

`source` 对象：`url`（必填）、`commit`（必填、可为 `null`）、`reference`（可选）。展示接受 `commit: null`；**不得编造提交或默认仓库 HEAD**；仓库 commit 与产物摘要是两个事实，不得互相推断。

### 3.4 插件与皮肤字段（采用对方第 6 节）

- `requiresDsh`：可为 `null`，配 `compatibilityBasis` 三选一（`author-declared` / `maintainer-target` / `unknown`）；非 unknown 时必须给 `compatibilityReference` HTTPS 出处。
- **兼容声明由作者/供货方如实提供，Mojobox 不擅自扩大范围**；EAC 市场仍须核对真实 `package.json`、依赖与宿主能力。
- `artifact`：可选；一旦提供必须四字段完整——`format`（`npm-tgz`）、`downloadUrl`（匿名 HTTPS 文件直链）、`sha256`（64 位小写、**无 `sha256:` 前缀**；我方导入器兼容历史带前缀写法，但正式供货不带）、`size`（真实字节数正整数）。
- 同一 `packageName + version` 的产物字节不可替换；换字节必须升版本；下载地址可换同字节镜像，但摘要、大小、身份必须一致。
- `license`、`authorization`（`basis`/`reference`/`redistribution`）可选；缺失表示未知，**不能通过默认值变成允许再分发**。

### 3.5 `material`（采用对方第 5 节）

必须 `installable: false`；不要求宿主兼容信息；**一期禁止携带 `artifact`、`components`、`execution`**；无作者版本时由资料记录维护者声明记录版本。

### 3.6 皮肤 `appearance` 对象（采用对方第 7 节）

- `loadingMode`：`standalone-plugin` / `loader-based` / `unknown`；`loader` 仅 `loader-based` 时必填。
- **独立主题插件不强制填写不存在的 loader**；未知加载方式不进入皮肤切换流程。
- `skinIds` 为数组（单插件可注册多个主题）+ `skinIdsKnown`；`conflicts` + `conflictsKnown` +（known 为 true 时）`conflictsReference`；未知如实标未知，**不表示已验证无冲突**。
- `previews` 可为空；固定来源优先，外部可变图片不算固定产物。
- 市场区分**可下载 / 可安装 / 可切换**三种能力，不视为同一能力。

### 3.7 整合包（采用对方第 8 节）

- 保留作者原始 `.dshpack` 薄包；薄包 `artifact` 可原样下载，**但不得作为插件 `.tgz` 交给插件安装器**。
- `components` 必填至少一个；组件 `version` 允许作者引用约束（如 `^1.0.0`），不与顶层精确版本混淆；`ref` 原样保留 npm / `github:owner/repo` / `builtin:` 形式。
- `execution` 必填；未知写 `unknown`；`complete` 必须有核对出处 `reference`；`complete + edges: []` 在有出处且确无关系时合法。
- `edges` 两端必须引用 `components[].id`，禁止自依赖、成环、引用不存在的组件；`milestone` 只有 `installed` / `active`。
- **`resolved` 绑定**：组件引用同一快照中已有完整 `artifact` 的 active 插件/皮肤记录（包名、精确版本、摘要三一致），市场再绑定自己的真实 `releaseId`，不生成假发行。
- **市场开放组合安装的七个必要条件**（缺一即保持展示、不开放一键安装）：无撤回、全部组件已解析绑定、参与策略明确、来源与授权通过核对、`coverage: complete` 且执行图合法有出处、宿主条件满足、用户确认后由宿主执行。
- 多皮肤组合不默认"安装后全部启用"。

## 4. 展示与安装两档（采用对方第 3、10 节）

供货记录进入市场后分为四类处理：

1. **来源展示**：缺产物、兼容未知的插件——展示来源，不生成安装发行；
2. **资料展示**：`material`——只展示与访问来源，任何安装路径都拒绝；
3. **安装候选**：产物四字段齐全且通过我方全部核对；
4. **不可安装组合**：组件未解析或条件不齐的套餐——照常展示、保留原始下载，不伪装一键安装。

**我方对"缺产物即拒收"的修正**：接受对方"两档"方案，替换我方 v1 第 8 节中"缺 `artifact` 拒收"的表述；改为"缺 `artifact` 拒绝进入安装候选，但接受为来源展示"。

## 5. 发布与撤回共识（采用对方第 9 节）

1. 固定发布说明入口 `supply-receipt.eac/v1`（`sourceId`、`sequence`、`revision` + 不可变清单的 `catalogUrl`、`sha256`、`size`、`sourceCommit`）；说明与清单三要素必须一致。
2. 先上传并复核不可变快照，再更新发布说明；不公布尚不能下载的批次。
3. 相同序号只接受完全相同字节；低序号、同序号不同字节均拒绝。
4. 我方获取、核对、转换成功后**原子接受**新批次；失败保留已接受目录并报告错误。
5. 撤回记录永久保留；版本升级不得删除旧发行与撤回记录；**撤回版本不得自行恢复 `active`**，恢复需双方另行约定显式审核流程。
6. 此前接受过的记录无撤回即从快照消失 = 非法快照，拒绝。
7. 已装组件撤回时，使用它的组合同步关闭对应安装路径。
8. 安全边界：HTTPS + SHA-256 只做传输与字节核对，不是恶意代码检测或发布签名；我方预先登记并信任入口、限制大小与重定向、不接收任意输入网址；清单上限 8 MiB，产物下载沿用我方既有安全规则。

| 2 | 缺产物、兼容未知的插件，以及组件未解析的整合包，只展示不安装？ | **同意**。见第 4 节；对应我方 `listings` 与"套餐照实展示"机制 |

| 4 | 独立皮肤不强制 loader，未知注册 ID、冲突和预览不补造？ | **同意**。并确认"可下载 / 可安装 / 可切换"分开显示 |

## 7. 落地顺序与验收（双方沿用对方第 11 节）

1. **第一步 · 确认契约**：双方确认本共识 → 共同确定正式 JSON Schema 与正反测试样本。**正式 v1 按类型限定字段，不静默接受未知类型、不把未知安装字段传给宿主；不兼容改动发布新版本端点。**
2. **第二步 · 一个真实插件 + 一条资料**：按第 6 节第 7 问的样本执行；我方导入、提取元数据、通过内部目录校验；资料任何安装路径都拒绝；插件安装测试使用隔离环境；静态校验与运行验收分别记录。
3. **第三步 · 一个真实皮肤**：核对真实协议与加载入口，未知不补造。
4. **第四步 · 一个小组合**：先验证未知依赖图时只展示，再验证真实组件绑定、执行图与隔离安装；组合安装不阻塞其他资源的来源展示。
5. **必测反例**：完整采纳对方第 11 节的 12 条反例表作为双方共同验收清单。

## 8. 待定事项（本共识不锁定）

- 正式 JSON Schema 文件位置与最终字段名；
- 供货端点的实际 HTTPS 地址；
- 旧版端点保留时间（须给出明确期限，不使用"一个版本周期"的含糊表述）；
- 导入器上线时间与导入频率；
- `workflow` 包的映射方式；
- 运行证据格式；
- 撤回恢复的显式审核流程；
- 首个样本最终是否替换。

## 9. 不变边界（任一方不得突破）

1. 不修改作者原始产物，不为对接改变 `.dshpack` / Manifest 原字节。
2. 不把未知写成保证：未知兼容、未知冲突、未测运行状态一律如实标注。
3. `verified` 只能来自具体宿主与环境的实机验收，静态检验永远不等于运行证据。
4. Mojobox 不做安装器、不承诺安装成功；EAC 市场不关闭官方保护、不伪造安装结果。
5. 缺授权材料的内容不进入镜像分发与安装发行。
6. 不复用序号、不静默覆盖同版本字节、不删除未撤回的历史记录。
